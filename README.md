## 1. LLM 모델 비교·선정 및 평가 보고서

### 1.1 비교 평가 목적 및 평가축 정의
유튜브 채널 운영 과정에서 '기획안 및 영상 대본(스크립트) 작성' 업무에 투입할 최적의 LLM을 선정하기 위해 3종의 모델을 비교·평가합니다.

* **평가축 정의 (4개 영역)**
  1. **구어체/대본 자연스러움 (Spoken Fluency)**: 유튜브 영상 특성에 맞는 구어체(~했는데요, ~일까요?) 및 입말 표현의 흡입력.
  2. **형식 준수율 (Format Adherence)**: 지정된 목차(썸네일/제목/Hook/본문/CTA) 및 마크다운 출력 규격 준수 여부.
  3. **제약사항 준수 및 환각 제어 (Constraint & Safety)**: 근거 없는 수치 지어내기 금지, [확인 필요] 표기 준수 여부.
  4. **장기 문맥 유지력 (Context Retention)**: 10턴 이상 대화 진행 시 초기 페르소나 및 조건 변경(톤 변경, PPL 추가 등) 이행력.

### 1.2 비교 대상 모델 및 평가 결과표 (정량 점수 + 근거)

* **테스트 일자**: 2026-08-03 | **설정**: Temperature `0.7`, Top_P `0.9`

| 평가축 | 평가 기준 | GPT-4o (유료) | Claude 3.5 Sonnet (유료) | Gemini 1.5 Pro (무료) |
| :--- | :--- | :---: | :---: | :---: |
| **1. 구어체/자연스러움** | 대본 구어체 흡입력 및 문장 매끄러움 | **5 / 5** | 4 / 5 | 3 / 5 |
| **2. 형식 준수율** | 지정된 출력 서식 100% 준수 여부 | 4 / 5 | **5 / 5** | 4 / 5 |
| **3. 제약 및 환각제어** | 출처 없는 수치/정보 억제 능력 | 3 / 5 | **5 / 5** | 3 / 5 |
| **4. 장기 문맥 유지력** | 10턴 이상 대화 시 제약조건 유지율 | 4 / 5 | **5 / 5** | 3 / 5 |
| **총점** | **20점 만점 기준** | **16점** | **19점** | **13점** |

#### 모델별 정량점수 부여 근거
* **GPT-4o (16점)**: 대본의 구어체 표현이 가장 매끄럽고 자연스러우나, 자극적인 썸네일 카피 작성 시 원문에 없는 통계 수치(예: "90%가 모르는")를 임의 창작하는 환각 현상 관찰됨.
* **Claude 3.5 Sonnet (19점)**: 템플릿 구조화 능력이 가장 뛰어나며, '출처 없는 수치 작성 금지' 제약 조건을 정확히 이행하여 `[수치 확인 필요]` 태그를 안정적으로 출력함. 장기 대화 문맥 유지력 최고점.
* **Gemini 1.5 Pro (13점)**: 무료로 대용량 컨텍스트 활용이 가능하나, 5턴 이상 대화 진행 시 초기 페르소나 말투가 무너지며 문어체 설명문이 섞이는 현상 발생.

### 1.3 업무 기준 최종 모델 선정 결론
> **최종 선정 모델: Claude 3.5 Sonnet (메인) + Gemini 1.5 Pro (보조)**
> 
> * **선정 근거**: 유튜브 콘텐츠 특성상 자극적인 가짜 뉴스로 인한 채널 신뢰도 하락 방지가 최우선임. Claude 3.5 Sonnet은 환각 제어 성능과 지시사항 이행도가 가장 뛰어나 메인 대본 작성용으로 최적임.

### 1.4 API 비용 절감 및 무료 모델 활용 전략
1. **Hybrid 연동 전략**:
   * **1단계 (아이디어 수집/초안)**: 무료인 Gemini 1.5 Pro를 활용해 자료 요약 및 아이디어 브레인스토밍 수행.
   * **2단계 (최종 대본/기획안)**: 유료/고성능인 Claude 3.5 Sonnet에 프롬프트를 전달하여 최종 정제.
2. **토큰 절감 후처리 방안**:
   * 대화 세션 누적 시 불필요한 이전 대본 원문은 시스템 입력단에서 정기적으로 요약(Context Compression)하여 입력 토큰 절감.

## 2. 프롬프트 엔지니어링 및 시스템 설계서

### 2.1 시스템 프롬프트 vs 유저 프롬프트 구조 분리 명세

```text
================================================================================
[SYSTEM PROMPT] - LLM 역할, 페르소나, 운영 원칙, 행동 제약 설정 (고정 영역)
================================================================================
[System Role & Persona]
당신은 구독자 100만 지식/정보 채널 출신 베테랑 메인 작가 'Script-Master'입니다.
목표: 입력된 아이디어를 바탕으로 시청자 이탈을 방지하는 표준 유튜브 기획안 및 대본 작성.

[Operational Principles]
1. Hooking & Retention: 오프닝 30초 내 시청자 호기심 자극 (질문/공감형 문장 시작).
2. Spoken Language: 대본은 무조건 실제 입으로 읽기 자연스러운 구어체 사용.
3. Guardrail: 원문에 없는 구체적 수치 창작 금지. 미확인 정보는 '[수치 확인 필요]'로 명시.

[Output Format Specification]
- 1. 썸네일 카피(2개) & 제목 후보(3개)
- 2. 오프닝 Hook 대본 (30초, 지시어 포함)
- 3. 본문 핵심 구성 (3단계)
- 4. CTA (참여 유도 멘트)

================================================================================
[USER PROMPT TEMPLATE] - 사용자가 매번 입력하는 데이터 템플릿 (가변 영역)
================================================================================
[과업 요청]
- 주제/원문: {USER_INPUT_TEXT}
- 채널 톤앤매너: {TONE_AND_MANNER} (예: 전문적인 해요체 / 친근한 반말)
- 필수 포함 요소: {SPECIAL_REQUIREMENTS} (예: PPL, 쇼츠용 멘트 등)
